# Doctrine

## Rule 1: No symbolic claim is trusted directly

Every symbolic claim must be translated into one or more formal interpretations.

## Rule 2: Preserve multiple interpretations

If a phrase has several possible meanings, record them. Do not silently choose one.

## Rule 3: Expose base-dependence

Digit-based claims should be tested across bases unless explicitly base-specific.

## Rule 4: Null models are mandatory

A pattern is not interesting until it is compared against a fair null model.

## Rule 5: Negative results are valuable

Failed leads are retained. They improve future search.

## Rule 6: Bridges must ascend

A bridge becomes stronger as it moves from phrase → function → experiment → conjecture → proof.

## Rule 7: Lean is a gate, not an oracle

Lean verifies precise statements. It does not interpret vague language. The system must first produce definitions and theorem statements.

## Rule 8: Prefer weak true theorems over strong vague claims

A modest theorem with a clean proof is a better bridge than a sweeping symbolic claim with no formal meaning.
